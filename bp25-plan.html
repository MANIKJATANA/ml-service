The next Round-3 build. One pass over the app's accumulated small rough edges — readability, keyboard/touch access, shareable links, and a few visual fixes — so the whole thing feels finished.

The problem we're fixing

Lots of small things are a little bit off — none fatal, but together they make the app feel unpolished.
Some data text is too light to read comfortably (fails the contrast standard). The month calendar crushes on a phone. A few tap targets are too small and a few links show no keyboard-focus ring. Filter a list, click into a row, press Back — and your filter is gone (it was never in the web address). Every browser tab just says "Photos". The sign-in screen is a plain gray card. The "matching now" spinner doesn't spin. And event category colors reuse the exact status colors, so a "Trip" tag can look like a "needs attention" warning.
Your call (already made): take all four groups below, in one phase. Mostly low-risk cosmetic + accessibility work; the two rounds of self-review are the safety net.

What we're building — four groups, one phase

AReadability & access (the floor) the one High
  • Readable data text — swap the too-light gray to the darker one everywhere it carries data (table headers, labels, counts, hints) so it passes the contrast standard. ~60 spots, colour only.
  • Calendar on a phone — it scrolls sideways instead of crushing; the "today" circle gets the darker, readable accent.
  • Keyboard & touch — focus rings on three bare links; bigger tap targets on the events checkboxes + the toast close button.
  • The photo viewer — a visible "← → · Esc" hint; and when a video is focused, the arrows control the video (not the gallery) instead of doing both.
  • Page titles — each browser tab reads its page ("Students · Photos", "Dashboard · Photos") instead of all saying "Photos".
BDesign residue (quick polish)
  • A brand moment on sign-in — the "Photos" name + mark above the card, instead of a bare gray box.
  • Category colors — a distinct, non-status palette, so an event category can never be mistaken for a "warning".
  • The frozen spinner — the "matching now" icon actually spins.
  • The one-time password — shown in a proper monospace so it's easy to read/copy.
CShareable list links the bigger one
  • Filters in the web address — search / sort / filter / status on the Students, Events, Staff, and Schools lists go into the URL, so a filtered view is shareable and survives the Back button (like the gallery tab already does).
DThe odds & ends
  • Skip-to-content link for keyboard users + a proper <main> on the sign-in screen.
  • Bulk-select students — a checkbox column + a bulk "Assign to class" bar (like the events list already has).
  • "You're offline" hint when the connection drops; scroll position better preserved on Back.
  • Search highlighting — the matched text is highlighted in the results; a second "Download all" at the bottom of a long photo page.

How we'll work

One phase — all four groups together, then the full check (types + lint + build) and a 2× self-review (the second pass focused on contrast + accessibility), then brought back to you. It's a large but low-risk diff — mostly colours, spacing, and wiring. Nothing is committed until you say so. Frontend-only — the review will confirm only frontend/ changed.

How we'll check it

The full frontend gate stays green, plus a walk: the lightened text now reads clearly; the calendar scrolls on a narrow screen; the links/targets are keyboard- and touch-friendly; the video-arrow fix works; each tab shows its page name; the sign-in has a brand; categories don't look like statuses; a filtered list is shareable and survives Back; the skip-link, offline hint, student bulk-assign, search highlight, and bottom "Download all" all work.

Not in this build (noted honestly): the "quiet" input border stays as-is (a deliberate tradeoff — labels + a strong focus ring carry it); full scroll-position memory on the long infinite lists is best-effort only; dark mode and a few parked polish items are still parked. No server change, no database migration, no ML change. After this, the roadmap tail is BP23 (instrumentation) → BP24, plus the earlier blocked student "This isn't me" safety whenever you re-open it.
