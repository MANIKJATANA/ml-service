Kaise banega

Backend (do chhote endpoints — reuse, koi migration nahi)

  • Preview: POST /v1/events/{id}/photo-recipients + media_ids → per-student {name, photo_count, opted_in, has_number} — jo students in photos me effectively aate hain (BP5 overlay, rejected excluded). Kuch bhejta nahi.
  • Send: POST /v1/events/{id}/whatsapp-send-photos + media_ids → server har consenting student (opted-in + number) ko unki wali selected photos bhejta hai — pehle se bani WhatsAppShareService machinery se (effective intersection + budget cap + send-log + PII-free). Ek summary return.
  • Dono GalleryService (appearances) + WhatsAppShareService reuse karte hain. Permission whatsapp:send (admin+teacher). Koi migration, koi ML change nahi.

Frontend

  • All-photos select bar me "Send to appearing students" button (jab ≥1 selected).
  • Click → preview fetch → dialog (kisko-kitni + total messages + skipped) → Confirm → send → honest toast ("Sent to N students, X messages · Y skipped").

✅ Server sab gates lagata hai (consent, effective set, budget, PII) — FE sirf preview dikhata + confirm karta.

⚠️ Zaroori — ek purana decision reverse ho raha

Photo-fanout (ek photo → usme aane wale sabko) ko decision 0094 (W2) me deliberately reject kiya tha ("too risky") — tab student-centric (ek student → uski photos) chuna tha. Ye feature wahi photo-fanout wapas laata hai.

Kyun ab theek hai: (1) bhejne se pehle preview + confirm ("ek baar dikhade"), (2) sirf opted-in + number wale ko jaata hai, (3) budget cap lagta hai, (4) sirf effective appearances (reject/hataye hue nahi). Tera ye request hi iska sign-off — bas record kar dunga (naya decision).

Honest limits
  • Cost: fan-out me messages = Σ (har student ke liye uski selected photos). Preview me total dikhega taaki surprise na ho; budget cap cross hone pe baaki skip.
  • Sirf opted-in + number wale students ko — baaki preview me "skip" dikhenge (unke liye By-student / detail se number/opt-in set karo).
  • Send server-side loop (per student), best-effort — kisi ek ka fail poora batch nahi rokta; summary me sab dikh jaata.
  • "All photos" tab server-paginated hai — select sirf loaded (scroll-in) photos pe (jaise abhi download-select). Poore event ki har photo ek saath select karne ka "select-all-across-pages" abhi scope se bahar.

TL;DR — All-photos me photos select → "Send to appearing students" → preview (kisko kitni + total messages + kaun skip) → confirm → server har consenting student ko unki photos bhejta hai. 2 chhote backend endpoints (reuse, no migration) + FE bar+dialog. Note: ye 0094 ka "no photo-fanout" reverse karta — preview+consent+budget se guard, tera sign-off record kar dunga. Approve kare to bana du.
