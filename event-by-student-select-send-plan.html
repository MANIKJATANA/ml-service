Plan — Event gallery "By student" pe select / random send

Jo student-detail "Appears in" pe kiya (0100), wahi yaha bhi. Abhi sirf plan — tu approve kare tabhi implement.

Abhi kya hai

Event gallery ke By student tab pe: ek student chuno → us event me uski photos dikhti hain → "Send all N on WhatsApp" / "Download all N". Bas — subset chunne ka koi tarika nahi (ya to poori bhejo ya kuch nahi).

Ye tab pehle se ek event + ek student pe scoped hai — to yaha event filter (Phase 2) ki zaroorat nahi. Bas select/random wala division (Phase 3) chahiye.

Default (browse) me tile → lightbox, aur Send/Download = poore student ke event-photos (jaise abhi). "Select photos" dabao → select mode: Select all · Random N · manual tap → Send K / Download K.

Kya badlega

❌ Abhi

  • Student chuno → "Send all 12" / "Download all 12"
  • Subset ka option nahi

✅ Ab

  • "Select photos" → grid pe tap-to-select
  • Select all · Select random N · Clear + "K selected"
  • Send K / Download K — chuni hui photos
  • Browse me pehle jaisa (poora student) + lightbox
Kaise banega (saaf-suthra)
  • Ek shared component nikaal denge — student-detail "Appears in" ka select-toolbar + Send/Download-on-target logic ko ek reusable piece (e.g. StudentPhotoActions) me. Dono jagah wahi ek code chalega (DRY), duplicate nahi.
  • By-student tab pe wahi component: media = useEventStudentMedia(eventId, studentId) (jo tab pehle se load karta hai), single-event — koi event filter nahi.
  • Send pehle jaise SendPhotosButton se (server media_ids ko effective-set se intersect karta hai → koi entitlement change nahi); Download useDownloadAll se (zip naam event/date se).
  • Selection student badalne pe clear ho jaayega (stale-safe) — dusre student ki photos galti se na jaaye.

✅ Pure frontend — koi backend/ML change, koi migration, koi nayi permission nahi. (Subset send pehle se supported hai.)

Honest limits
  • Sirf By student tab (single event-student). "All photos" tab pe multi-student select abhi scope se bahar.
  • Random select client-side (loaded photos me se); BP9 ka 500-photo non-streaming download cap waise hi lagu.
  • Refactor me student-detail "Appears in" bhi shared component use karega — usko dobara verify karenge (koi behaviour change nahi, sirf code share).

TL;DR — By-student tab pe wahi Select all · Random N · manual → Send K / Download K (Phase 3 jaisa). Ek shared component dono jagah. Event filter nahi (single event). Pure frontend, koi backend change nahi. Har cheez ke baad gate + 2× review. Approve kare to bana du.
